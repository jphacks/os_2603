# FusenLess 利用者検証計画

この文書は今後の検証手順です。計画・記録用の項目を、実施済みの結果や学習効果として扱わないでください。既存の試用記録は、日時・アプリの版・条件を確認してから結果と分けて記載します。

## 確かめること

| 評価上の課題 | 確かめる問い | 残す記録 |
| --- | --- | --- |
| 貼った意図を思い出せるか | 本が手元にない状態で、本人が貼った理由を説明できるか | 説明できた件数 / 対象付箋数、手掛かりにした情報 |
| 想定ユーザーに使ってもらえるか | チーム外の人が、補助なしで付箋作成・再確認まで進めるか | 完了数 / 参加人数、補助した操作、使いたい場面・困った点 |
| 元の箇所へ戻れるか | ページ番号とピン位置が正しく復元されるか | ページ正答数と位置正答数を別に記録。構図条件と手動修正も残す |
| 操作時間 | 範囲選択から保存まで、撮影開始から確認完了までに何秒かかるか | 各区間の秒数、端末、OCR失敗・再試行、AI有効無効 |

## 実施方法

1. チーム外の対象者に、本人が読む紙の教材を用意してもらう。参加人数は実数を記録し、少人数の結果を一般化しない。
2. 説明文と操作説明を全員で揃える。最初の練習は計測と分ける。
3. 教材を選ぶ、撮影、範囲選択、付箋追加、メモ・色の編集、完了、一覧で確認という流れを試してもらう。補助をしたら記録する。
4. 範囲選択開始から付箋追加の保存までと、撮影開始から完了後の一覧表示までを別々に計測する。メモの長さと入力方法も記録する。「貼るだけ」とメモ込みの時間を混ぜない。
5. 同じページを撮り直す。同程度の構図と、角度・余白を変えた構図を別条件で記録する。復元前の手動調整はしない。
6. ページ番号の正誤と、ピンの中心が本人の意図した領域内にあるかを別に判定する。ページ誤認識や再読取を成功例から除外せず、全試行の内訳として残す。
7. 本を一時的に閉じた状態で付箋を探し、なぜ貼ったのか説明してもらう。「覚えているはず」という誘導はせず、説明できたか本人に確認する。これは貼った意図の再確認であり、教科書の知識の長期定着とは分ける。
8. 分からない付箋を「あとで確認」に残し、紙のページを開き、「教科書で確認した」を記録できるか確かめる。
9. 自由回答で、役に立つ場面・引っかかった操作・今の方法から変えたいか、その理由を聞く。

比較をする場合は、同程度の文章量・メモ内容で条件を揃え、物理付箋とアプリを使う順番を参加者間で入れ替えます。電子書籍や他アプリの速度を測っていなければ、優劣を数値で断定しません。

## 記録項目

個人名ではなく参加者IDを使い、公開用には本人が公開を了承した感想と集計値を用います。

| 項目 | 内容 |
| --- | --- |
| 実施条件 | 日時、参加者属性、アプリのコミット、端末、OS、AIの状態 |
| 操作 | ページ、文字量、メモの長さ、入力方法、操作区間ごとの時間 |
| 成否 | OCRの成否、ページ正答、ピン位置正答、補助と再試行の回数 |
| 振り返り | 貼った意図を説明できたか、本の箇所を探せたか、確認記録を残せたか |
| 感想 | 実際の発言と要約を区別。提案・不満・肯定的意見をいずれも記録 |

## READMEへの反映形式

結果が揃ってから、次の形式で追記します。未確認の欄を推測して埋めません。

- 実施日時・対象・人数・試用した版
- 実際に試した操作と条件
- 成功した件数 / 全試行数。補助あり・再試行・失敗を分ける
- 操作時間は対象人数・試行数・計測区間とともに示す
- 実際の感想。逐語引用と要約を区別する
- 観察から分かったことと、次に直すこと

同日の短い試用結果から「記憶が定着した」「学習効果が最大化した」と結論付けません。長期の知識保持を主張するには、別の時点での追跡と条件を揃えた比較が必要です。
